# Shared tag picker

`TagPickerProvider` lives inside the persistent library model and outside the command owner. Compact + and Regular New tag open catalog mode: search existing tags, choose AND filters or create a tag. Cmd/Ctrl+T and preview Add tag open snippet mode with a captured snippet ID. Filter rows and the Regular preview use one measured chip row with a +N overflow trigger. Filter chips sort selected IDs first; preview badges reserve source/time metadata and a fixed header height. The filter picker has checkbox/count rows and a selected-count/Clear footer. Snippet mode shows assigned tags in saved addition order when the query is empty, and matching assigned tags before other catalog matches when searching. Remove actions and keyboard toggles save each change immediately; the picker stays open.

The picker reads the library model's tag catalog/counts rather than maintaining another cache. Committed snippet/tag revisions refresh the catalog and the open target's assignments; deleted filter IDs are removed while retaining the selection cursor's desired ID. Each picker session and read has a generation. A delayed write retains its original target, while stale completion cannot change a newer session's assignment state. Closing the picker does not retry or cancel an already accepted mutation.

Two additive typed operations run through the existing `LibraryMutations` queue and worker transaction:

- `ensureTag({name, snippetId?})` resolves using `WHERE name = ? COLLATE NOCASE`, or creates through the existing repository/palette. An optional captured snippet is validated first and assigned within the same transaction. Clear/delete and assignment-limit failures roll back newly created tags.
- `setTagMembership({id, tagId, assigned})` changes one membership using the current stored set, preserving other concurrent assignments. Existing full-set/CRUD operations remain available.

Creation and rename input share trimming and JavaScript's locale-independent Unicode lowercase. Canonical stored names remain lowercase, 1–64 UTF-16 units, with well-formed Unicode. No normalization-form conversion or collation migration is performed. SQLite NOCASE remains the identity authority, including its embedded-NUL behavior; text reads use the existing BLOB decoder. Palette cycling is chosen by the repository, and a snippet remains limited to 100 tags.

Settings tag creation/editing retains named preset swatches and adds the native HTML color picker plus a six-digit hex field. Presets, the picker preview and valid hex edits share a local draft. Invalid hex edits retain the last valid preview, show an associated error and disable saving. Cancel closes without a mutation. Native picker cancellation leaves the draft unchanged. Saved custom values use lowercase `#rrggbb`; legacy named preset values remain accepted by IPC, SQLite reads and JSON imports. The existing text color column needs no migration. Every badge/dot uses the same sRGB palette resolver, including compact/regular rows, filters, tag assignment and preview/Settings badges. The native picker and hex field use the same resolved hex value for named presets.

The canonical storage library flow covers custom color creation, invalid-update rejection without a stored change, hex normalization, export/import/reopen, and existing named-color compatibility. Actual native picker interaction, keyboard/assistive-technology behavior and cross-window visual qualification remain manual checks.

The Command-in-Popover uses cmdk 1.1.1 and Radix primitives, with item UUIDs rather than tag names as command identities. Search is a lowercase literal substring. Picker-local Enter/Escape/composition handling stays inside the overlay and the library's single keyboard owner recognizes that overlay. Cmd/Ctrl+T also works from the snippet editor for the current command-eligible library selection; IME, repeated/prevented keys and modal ownership still block it. Opening or editing tags does not apply or discard the text draft. Close returns focus to the supplied trigger; clicking another interactive target preserves that target's focus.

The one functional flow runs the real controller against owned SQLite through a typed external IPC adapter, including reopen, case/NUL reuse, assignment/count/AND behavior and delayed target/clear outcomes. Its architecture exception permits only `src/main/snippets/tag-picker.test.ts` to import `tag-picker-controller`; application layer restrictions remain unchanged. Automated GUI/native tests are absent. Actual focus, composition, theme, CSP and assistive-technology behavior remain manual qualification. Regular entrypoint composition belongs to issue18, and Settings tag management/count UI belongs to issue22.

`TagOverflowRow` measures rendered chips, pinned controls and hidden tabular +N samples with ResizeObserver; changing tags, selection, fonts, layout or window width refits a complete prefix. Hidden chips stay measurable but are invisible, inert and excluded from accessibility. Long chip names use a 20-character display plus a full-name tooltip. The opening virtual anchor retains its last visible rectangle if fitting hides its trigger; Escape returns to that trigger or the row's add control. Membership reads use insertion order, and no-op reassignment keeps that order. JSON transfer preserves the stored membership order. The existing functional picker flow covers assigned-first query results and durable order on reopen; actual rendered fitting, focus, themes and assistive technology remain manual qualification.

Compact and Regular snippet items share `LibraryTagDots` in the same position before the text. Every assigned tag is rendered in stored order using the shared custom-color resolver: 6px squares with 2px gaps, filling down at most five rows before adding columns. The maximum 100-tag grid is 38px tall and 158px wide, fitting both fixed virtual row heights without hiding dots or changing virtualization. Dot hover titles and the item's accessible description retain the full assigned tag names.

Preview metadata is measured at its natural full width before fitting badges. The fixed-height header reserves the timestamp and required add/overflow control. If the full source plus time and that control cannot fit even with zero visible badges, only the source label uses an ellipsis; its full text remains in the accessible label and a tooltip available on hover or keyboard focus. Normal source names remain fully visible. This reversible fallback is a stated implementation assumption pending the user's optional preference, rather than an explicitly approved exception to the original never-truncated metadata rule.
