# [P16] Build the regular split view and snippet editing/actions

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Add full-text preview and snippet management while reusing library state.

## Scope

- Implement the 1.15fr/1fr list-preview split, wrapping chips, filter hint, dense single-line rows, relative times, keyboard footer, and full highlighted text.
- Separate SnippetPreview, SnippetEditor, SnippetActions, SnippetMoreMenu, and PreviewTagBar into individual files; reuse search/filter/query state across modes.
- Implement inline edit with explicit apply/cancel and keyboard behavior, Delete with bounded Undo, explicit Duplicate, safe Open source app, and Copy as Markdown code block.
- Use a Markdown fence longer than any backtick run in the snippet. Disable source activation with an explanation when no usable platform identity exists.
- Preserve selection when changing modes; tag/remove/copy/edit controls must not bubble into accidental row copy.

## Acceptance criteria

- [ ] Full text remains intact and selectable; canceling an edit changes nothing.
- [ ] Edit, duplicate, delete/undo update storage, counts, preview, and search results consistently.
- [ ] No selection, deleted selection, long text, and narrow Regular minimum size have usable states.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
