# [P25] Extend CI for application checks and Windows build smoke

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Catch module, behavior, and platform build regressions as implementation lands.

## Scope

- Preserve the existing Workflow validation job and pinned Actions conventions; add reproducible npm install, formatting/lint, strict types, functional service tests, and production build.
- Add Windows native build/package smoke once adapters land; keep OS permission/UI-dependent tests in a documented separate lane.
- Add npm Dependabot coverage and JavaScript/TypeScript CodeQL configuration only where supported; preserve the existing eligibility gate rather than assuming private scanning is enabled.
- Keep minimal canonical functional service tests, strict static checks, Windows packaging and CodeQL. No automated GUI/E2E harness.

## Acceptance criteria

- [ ] Existing workflow validation still passes; app checks fail on genuine type/import/test/build errors.
- [ ] Clean Windows builds use the lockfile and load required native modules.
- [ ] CI documentation distinguishes automated tests from real permission/fullscreen/native manual tests.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA and distribution requirements are manual Windows release checks where relevant. Performance measurements and budgets are skipped for this pass. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
