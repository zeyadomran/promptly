# P25: Extend CI for application checks and macOS/Windows build smoke

Catch module, behavior, and platform build regressions as implementation lands.

## Scope

- Preserve the existing Workflow validation job and pinned Actions conventions; add reproducible npm install, formatting/lint, strict types, unit/integration tests, and production build.
- Add Windows/macOS native build/package smoke once adapters land; keep OS permission/UI-dependent tests in a documented separate lane.
- Add npm Dependabot coverage and JavaScript/TypeScript CodeQL configuration only where supported; preserve the existing eligibility gate rather than assuming private scanning is enabled.
- Add Electron integration test harness and artifact retention for failures. Introduce required checks only after successful runs under repository policy.

## Acceptance criteria

- [ ] Existing workflow validation still passes; app checks fail on genuine type/import/test/build errors.
- [ ] Clean macOS/Windows builds use the lockfile and load required native modules.
- [ ] CI documentation distinguishes automated tests from real permission/fullscreen/native manual tests.

## Verification

Actionlint, clean build matrix, and a temporary intentionally failing check during setup; document required-check names.
