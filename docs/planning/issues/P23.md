# P23: Build first-launch onboarding with a real practice capture

Take new users from first launch to a successful capture using the real pipeline.

## Scope

- Build separate stepper, WelcomeStep, PermissionStep, ShortcutStep, TryCaptureStep, and footer components matching 760×510 references.
- On macOS, show actual Accessibility status, deep-link to settings, poll ~1 s while visible, stop polling on teardown, and auto-advance after permission. Skip the permission step on Windows and adjust step numbering.
- Reuse shortcut recording/validation; display a selectable sample prompt and route its capture through the production capture pipeline.
- Show the real toast and Saved. Nice. only after successful persistence; enable Open Promptly on success and retain a Skip route.
- Persist completion, open Compact on finish, and retain a successfully captured practice snippet. Skip creates no fabricated snippet; missing permissions remain recoverable in Settings.

## Acceptance criteria

- [ ] First-run flow differs correctly by OS and does not repeat after completion.
- [ ] Practice success is backed by stored data, with no duplicate synthetic event or fake toast.
- [ ] Back/skip/restart/revoked-permission paths remain usable and clean up polling/listeners.

## Verification

First-run profile tests, real permission grant flow, practice selection/shortcut capture, and skip/relaunch matrix.
