# [P10] Implement clipboard-preserving Copy fallback with concurrency protection

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Capture supported selections through Copy only when the original clipboard can be preserved.

## Scope

- Snapshot all restorable clipboard representations using the proven native adapter; distinguish empty clipboard from unavailable data. Do not reduce rich clipboard contents to plain text.
- Serialize app clipboard operations, inject the correct Copy action for the source app, wait for an observed clipboard change, read text, and restore in a finally path.
- Use clipboard ownership/change counters to avoid restoring over a newer user/external copy; do not infer freshness from text equality alone.
- Bound waits and memory, prevent nested capture, ignore stale clipboard content after timeout, and refuse fallback for formats or applications that cannot be handled safely.
- Validate helper failures/crashes and document the recovery model. Never persist clipboard snapshots or print their contents in diagnostics.

## Acceptance criteria

- [ ] Text, HTML/RTF, images, file lists, and supported custom formats round-trip unchanged in the validated matrix.
- [ ] A concurrent user copy wins; timeout, empty selection, error, and cancellation do not replace the clipboard with stale data.
- [ ] A running terminal command cannot be interrupted by an assumed Ctrl+C copy action.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
