# [P17] Unify copy commands, keyboard navigation, and keep-open feedback

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Make all library copy paths and shortcuts behave consistently.

The user's current keep-open copy and library UI requests supersede the earlier hide preference and whole-preview scrolling requirements. Supplied designs and historical receipts remain unchanged.

## Scope

- Route row click, Enter, preview Copy, Markdown copy, and later tray copy through one copy service using full stored text.
- Record copyCount/lastCopiedAt once after clipboard write succeeds; keep the window open and show accessible in-app Copied feedback for ~1500 ms.
- Keep copying visible for existing automatic/always profiles; select and highlight the copied row for Regular preview, preserving its ID through refresh/reorder without replacing a later deliberate selection.
- Implement arrows, Enter, Cmd/Ctrl+F, Cmd/Ctrl+T, Delete/Backspace with Undo, Cmd/Ctrl+comma, and Esc clear-then-hide.
- Scope shortcuts by focus/overlay: arrows/Enter in search may navigate/copy, but Delete/Backspace edits text; editor, IME, menus, dialogs, and tag picker keep their own keys. Emit the tag-picker command for P18.

## Acceptance criteria

- [ ] One gesture produces one clipboard write and one statistic increment.
- [ ] Text editing never deletes snippets, and dialogs/IME are not interrupted.
- [ ] Copy errors leave counters unchanged and do not hide the window.
- [ ] Confirmed copy shows an accessible in-app "Copied" notification; failed/uncertain copy shows no success and partial statistics failure never replays copy.
- [ ] Row click, preview Copy, Enter and Markdown use the shared service. The copied row stays highlighted and appears in Regular preview through asynchronous refresh/reorder; later selection wins. Compact does not switch modes automatically.
- [ ] The first selected row cannot obscure the list focus outline. Rows have subtle hover feedback and a pointer cursor without changing virtual row measurements; reduced motion is respected.
- [ ] Long preview text scrolls independently, keeping metadata and Copy/Edit/More visible.
- [ ] Sort and header tooltips use the existing portal and stay clear of the header. Header actions are icon-only with accessible names/tooltips, more spacing, and a contrasting selected view; the bottom border is visible below Windows caption buttons.
- [ ] Clickable controls use a pointer cursor; the existing shortcut recorder explicitly explains how to click or use Enter/Space to change the binding.
- [ ] Rows omit the visible Copy label while retaining an icon and accessible copy hint. Settings sits immediately left of the Compact/Regular switcher; touched button labels have no ellipses.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA and distribution requirements are manual Windows release checks where relevant. Performance measurements and budgets are skipped for this pass. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
