# [P17] Unify copy commands, keyboard navigation, and hide-after-copy behavior

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Make all library copy paths and shortcuts behave consistently.

## Scope

- Route row click, Enter, preview Copy, Markdown copy, and later tray copy through one copy service using full stored text.
- Record copyCount/lastCopiedAt only after clipboard write succeeds; update counts immediately and keep the visible Copied state for ~1500 ms when the window remains open.
- Apply auto/explicit hide-after-copy preferences; clicking a regular row selects it before any optional hide.
- Implement arrows, Enter, Cmd/Ctrl+F, Cmd/Ctrl+T, Delete/Backspace with Undo, Cmd/Ctrl+comma, and Esc clear-then-hide.
- Scope shortcuts by focus/overlay: arrows/Enter in search may navigate/copy, but Delete/Backspace edits text; editor, IME, menus, dialogs, and tag picker keep their own keys. Emit the tag-picker command for P18.

## Acceptance criteria

- [ ] One gesture produces one clipboard write and one statistic increment.
- [ ] Text editing never deletes snippets, and dialogs/IME are not interrupted.
- [ ] Copy errors leave counters unchanged and do not hide the window.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA and distribution requirements are manual Windows release checks where relevant. Performance measurements and budgets are skipped for this pass. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
