# P14: Implement substring search, filter syntax, sorting, and paginated queries

Return correct, responsive search results for at least 10,000 snippets.

## Scope

- Parse tag: and from: alongside free text; define quoted names, incomplete tokens, literal punctuation, unknown filters, and escaping without exposing raw SQL/FTS syntax.
- Use case-insensitive substring semantics, AND across selected tags and tag: tokens, intersection with source/free text, All reset, and Regular Untagged.
- Evaluate FTS5 trigram plus a correct short-query path or an in-memory index; ordinary token FTS alone does not fulfill substring matching. Verify Unicode behavior and 1–2-character searches.
- Implement all four stable sorts, counts, pagination, stale-response protection, and shared match ranges for safe renderer highlighting.
- Budget the full input-to-painted-results path under 50 ms at 10k; debounce must fit inside that budget, not add 50 ms to a 50 ms query.

## Acceptance criteria

- [ ] Substring, punctuation, Unicode, AND-tag intersection, Untagged, all sorts, and combined syntax have documented correct results.
- [ ] Capture/edit/tag/delete/import changes invalidate the index and counts consistently.
- [ ] Benchmarks include short/worst-case queries and rapid typing, not only query execution.

## Verification

Parser/repository fixtures, literal wildcard tests, index consistency tests, and reproducible 10k end-to-end benchmark.
