# [P21] Implement shared shortcut recording and shortcut settings

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Let users safely configure capture and window shortcuts with one reusable recorder.

## Scope

- Build ShortcutRecorder, ShortcutKeycaps, CaptureShortcutMode, ModifierSelector, and ShortcutConflictStatus as separate files for Settings and onboarding reuse.
- Support recording/cancel/clear where optional, key-combination validation, Windows key labels, double-tap mode selection, and 150–600 ms slider.
- Show known reserved/system conflicts and actual registration failures; say availability is limited to detectable conflicts rather than claiming every app was checked.
- Wire show/hide, optional pin, confirmation toast, and normalization settings; preserve previous bindings after failure and suppress recording-triggered capture.
- Explain Windows Alt+Space conflict when detected and offer a tested alternate such as Ctrl+Alt+Space without silently replacing the user's choice.

## Acceptance criteria

- [ ] Recorder is fully keyboard usable with a clear Press a key state and Escape cancellation.
- [ ] Invalid/conflicting bindings do not replace working shortcuts.
- [ ] Onboarding and Settings share the same validation and components.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA and distribution requirements are manual Windows release checks where relevant. Performance measurements and budgets are skipped for this pass. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
