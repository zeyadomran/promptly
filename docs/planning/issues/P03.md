# P03: Validate native capture, keyboard hooks, and clipboard feasibility on both OSes

Resolve the platform risks before committing the production capture implementation.

## Scope

- Build a disposable capture harness for macOS AXSelectedText and Windows UI Automation TextPattern, foreground app identity, modifier hooks, and clipboard fallback.
- Compare maintained native packages against small packaged native helpers; record licenses, supported Electron ABI/architectures, permissions, helper lifecycle, and rebuild/signing needs. Select adapters behind stable interfaces.
- Test editors, Chromium browsers, terminals, no selection, revoked permission, Windows elevated apps, and macOS Secure Input. Validate terminal-specific Copy behavior; Ctrl+C must not interrupt a running command.
- Investigate multi-format clipboard snapshots, ownership/change counters, unsupported/lazy formats, failure restoration, and crash behavior. If faithful restoration cannot be established, skip destructive fallback.
- Measure capture-to-feedback on each path; identify any extra macOS Input Monitoring requirement imposed by the chosen hook. Confirm Alt+Space availability instead of assuming it.

## Acceptance criteria

- [ ] A documented support matrix contains real observations from macOS and Windows, with OS/architecture and app versions.
- [ ] Adapter choice and packaging proof exist for both platforms; unsupported paths return explicit errors without overwriting the clipboard.
- [ ] The ADR records outstanding release blockers, including failures of the under-150-ms target; no untested claim of universal capture.

## Verification

Human-in-the-loop runs on real machines, format round trips and concurrent-copy tests, foreground-window assertions, latency traces.
