# [P03] Validate native capture, keyboard hooks, and clipboard feasibility on Windows

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Resolve the platform risks before committing the production capture implementation.

## Scope

- Qualify the existing Windows UI Automation TextPattern adapter, foreground app identity and modifier hook through bounded manual checks. Clipboard fallback #12/P10 is deferred outside v1. Do not add another native test harness.
- Compare maintained native packages against small packaged native helpers; record licenses, supported Electron ABI/architectures, permissions, helper lifecycle, and rebuild/signing needs. Select adapters behind stable interfaces.
- Test editors, Chromium browsers, terminals, no selection, revoked permission, Windows elevated apps, and protected input. Native capture must not invoke Ctrl+C or read/write the clipboard; unsupported/failed/empty selections save nothing and report truthful state.
- Keep deferred fallback safety research in P10; it is not a v1 dependency or release gate. Explicit snippet/Markdown/tray Copy and its clipboard qualification remain in scope.
- Verify capture feedback without focus theft. Confirm Alt+Space availability instead of assuming it.

## Acceptance criteria

- [ ] A documented support matrix contains real observations from Windows, with OS/architecture and app versions.
- [ ] Adapter choice and packaging proof exist for Windows; unsupported paths return explicit errors without overwriting the clipboard.
- [ ] The ADR records outstanding native safety/support blockers and historical timing failures; timing budgets do not gate this pass, and no untested claim of universal capture is made.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA and distribution requirements are manual Windows release checks where relevant. Performance measurements and budgets are skipped for this pass. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
