# [P28] Verify Windows reliability, performance budgets, and release readiness

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Demonstrate that Promptly meets its native safety and responsiveness requirements in packaged builds.

## Scope

- Run the complete highlight→shortcut→capture→toast→search→tag→copy flow on Windows, including hidden/minimized/pinned states and real applications.
- Benchmark 10k+ realistic snippets and long-text outliers: full input-to-painted results under 50 ms, trigger-to-toast under 150 ms; report p50/p95/max, sample counts, OS/hardware, warm/cold state, and accessibility/fallback paths separately.
- Measure idle total process-tree RSS and CPU over a defined interval, repeated window/capture cycles, and startup; propose a numeric memory budget from measured Electron baselines because the spec gives none.
- Exercise clipboard multi-format preservation/concurrent copy, permission revocation, unsupported apps, restart, database failure, display changes, sleep/resume, and offline usage.
- Confirm every issue acceptance criterion and install/signing check; record failures as release blockers instead of silently weakening requirements.

## Acceptance criteria

- [ ] A reproducible evidence report covers Windows x64 and packaged artifacts.
- [ ] Clipboard loss, false capture, focus theft, data loss, and unmet performance targets have no unresolved release blockers.
- [ ] Final checklist links automated results and manual evidence; account/signing/hardware gaps remain explicitly incomplete.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
