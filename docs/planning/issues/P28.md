# [P28] Verify Windows reliability and distribution readiness

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Demonstrate native safety, functional reliability and distribution readiness in packaged Windows builds.

## Scope

- Run the complete highlight→shortcut→capture→toast→search→tag→copy flow on Windows, including hidden/minimized/pinned states and real applications.
- Verify functional large-library search and durable restoration, including Unicode and long-text records. Performance measurements and timing/RSS/CPU budgets are skipped for this pass; historical measurements remain evidence only.
- Verify native capture never invokes Ctrl+C or reads/writes the clipboard and saves nothing on unsupported/failed/empty selections. Exercise explicit snippet/Markdown/tray Copy, permission/access-denial changes, unsupported apps, restart, database failure, display changes, sleep/resume, and offline usage. P10/#12 fallback is deferred/not implemented and is not a v1 gate.
- Confirm current issue acceptance criteria and distribution checks, including installer/artifact verification, install/upgrade/uninstall and data preservation; signing depends on available credentials. Record required-check failures as release blockers instead of silently weakening requirements.

## Acceptance criteria

- [ ] A reproducible evidence report covers Windows x64 and packaged artifacts.
- [ ] Clipboard loss, false capture, focus theft and data loss have no unresolved release blockers.
- [ ] Final checklist links automated results and manual evidence; account/signing/hardware gaps remain explicitly incomplete.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA and distribution requirements are manual Windows release checks where relevant. Performance measurements and budgets are skipped for this pass. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
