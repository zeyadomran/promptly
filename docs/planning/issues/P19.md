# [P19] Add tag management with rename, recolor, merge, and delete

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Maintain the tag library without losing associated snippets.

## Scope

- Build the Settings Tags table with counts, creation, rename, palette selection, merge target picker, and delete confirmation.
- Handle rename collisions clearly; merge in one transaction, union associations without duplicate joins, and remove the source tag.
- Delete only the tag and its associations; retain every snippet and update active filters, badges, counts, and search syntax results.
- Use individual component files for rows, editor, color picker, merge dialog, and delete dialog.

## Acceptance criteria

- [ ] Merge preserves all unique snippet memberships and recalculates counts.
- [ ] Rename/recolor is reflected in every open window immediately.
- [ ] Deleting an active filter tag cannot strand the user in an unexplained empty state.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
