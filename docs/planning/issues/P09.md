# [P09] Implement Windows selection capture and foreground application identity

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Read text selections through UI Automation with clear behavior for unsupported applications.

## Scope

- Implement the selected Windows UI Automation TextPattern adapter and GetSelection text ranges; record foreground process/app identity.
- Bound potentially stalled UI Automation calls off the Electron main thread; specify deterministic joining of disjoint selections.
- Handle unsupported providers, protected fields, elevated-process restrictions, and stale foreground handles without automatic elevation.
- Provide safe source-app activation by validated OS identity and structured diagnostics without snippet content.

## Acceptance criteria

- [ ] Supported editors, browsers, and terminals return complete text and nullable source metadata.
- [ ] No-selection and unavailable-provider cases are distinct; no unrelated clipboard text is returned as a selection.
- [ ] No focus change, elevation prompt, or main-process freeze occurs.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
