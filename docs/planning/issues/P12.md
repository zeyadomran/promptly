# [P12] Show the focus-safe save toast in a dedicated overlay window

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Confirm captures even when the main window is hidden without stealing focus.

## Scope

- Host Sonner content in a dedicated non-activating, non-focusable overlay with a narrow preload API; renderer Sonner alone cannot appear over other apps when main is hidden.
- Match the 290 px reference, logo, Saved to Promptly/Already saved title, one-line preview, relative time, and ~2500 ms dismissal. No actions or tagging controls.
- Respect show-confirmation and light/dark/system settings; position within the active display work area and handle DPI/multi-monitor changes.
- Bound burst behavior and timers; test Windows fullscreen limitations and avoid focus or taskbar entries.

## Acceptance criteria

- [ ] Keyboard focus and keystrokes remain in the source app during appearance and dismissal.
- [ ] Main hidden/minimized and pinned/unpinned cases all show the correct toast when enabled.
- [ ] No toast window leaks after repeated captures; disabled confirmation creates no visible overlay.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
