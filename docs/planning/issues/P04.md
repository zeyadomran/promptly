# P04: Implement SQLite persistence, migrations, and snippet repositories

Persist complete snippets and tag relationships locally with transactional behavior.

## Scope

- Store SQLite in Electron userData, with versioned migrations, foreign keys, parameterized queries, and serialized writes outside blocking UI work.
- Persist all specified snippet/tag fields plus the tag join table. Add optional platform app identity for safe source-app activation; sourceApp remains nullable display metadata.
- Implement capture upsert, get/list, edit, explicit duplicate, delete/undo, and successful-copy statistics. Hash plus exact-text comparison may accelerate lookup; do not make text globally unique because explicit Duplicate is allowed.
- Use updatedAt descending for Newest (so recapture resurfaces a snippet), createdAt ascending for Oldest, copyCount descending, and lastCopiedAt descending/nulls last, each with stable ID tie-breaking.
- Preserve tags and createdAt on recapture. Duplicate creates a new ID with copied tags and zero copy statistics. Bound undo snapshots and clear them on data erasure.

## Acceptance criteria

- [ ] Data, full Unicode/multiline text, tags, and copy counts survive relaunch.
- [ ] Recapture reuses a deterministic existing ID; deliberate duplicates remain possible.
- [ ] Migration failure preserves the previous database; writes and relationship changes are atomic.

## Verification

Temporary-database integration tests for migrations, rollback, reopen, concurrent capture, long text, duplicates, and delete/undo.
