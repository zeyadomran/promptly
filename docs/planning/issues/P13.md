# [P13] Implement desktop window lifecycle, size modes, and pin behavior

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Provide native-feeling compact, regular, onboarding, and settings windows.

## Scope

- Implement single-instance launch, open/show/hide/reactivate, tray-aware close, and explicit Quit cleanup; keep a recovery route when tray visibility is changed.
- Compact starts near 440 px wide with minimum height 420; Regular defaults to 1000×640 with minimum 760×480. Persist distinct bounds and clamp restored windows to available displays.
- Use Windows caption controls with safe draggable/non-draggable title-bar regions.
- Implement persisted pin behavior and Windows fullscreen support where available, platform-aware theme/size/pin controls, and ~180 ms resize animation only when supported and reduced motion permits.
- Onboarding uses its 760×510 layout; settings can resize across 640 px. Show/hide shortcut opens the current mode and focuses search.

## Acceptance criteria

- [ ] Mode toggles retain independent geometry without moving a window offscreen.
- [ ] Pin state agrees across title bar, footer, settings, and OS behavior after restart.
- [ ] Closing/hiding, a second launch, display disconnect, and Quit produce predictable lifecycle behavior.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
