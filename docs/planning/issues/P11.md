# P11: Connect the capture pipeline with normalization and deduplication

Turn a shortcut into one durable saved snippet while preserving source app focus.

## Scope

- Orchestrate foreground identity, preferred selection API, safe fallback, empty-text rejection, normalization, persistence, and result events.
- Normalize only when enabled: trim edges and remove a recognized first-line terminal prompt prefix; retain subsequent lines/indentation and avoid blanket replacement of code symbols.
- Deduplicate exact post-normalization text transactionally, preserve existing tags/createdAt, update updatedAt, and emit Already saved.
- Serialize/coalesce repeated triggers; handle pause, permission loss, cancellation, storage error, and unsupported capture without false success.
- Instrument trigger-to-persistence and trigger-to-feedback timestamps without logging snippet text.

## Acceptance criteria

- [x] The native Windows path emits saved/duplicate only after durable success; recapture creates no extra automatic duplicate.
- [x] Whitespace-only text is ignored; disabled normalization preserves exact selected content.
- [x] Capture never calls show/focus on main or settings windows.
- [ ] Safe clipboard fallback remains blocked on P10 / issue #12; issue #13 is not complete.

## Verification

One canonical public CaptureService functional flow uses real owned SQLite and external native/time/database-response boundaries. Current product scope is Windows only. Actual Windows capture, source activation and capture-to-toast latency need manual packaged qualification; no GUI/E2E or benchmark infrastructure is added. See [the implementation checkpoint](../../verification/P11-checkpoint.md).
