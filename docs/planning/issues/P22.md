# [P22] Add storage location, JSON/Markdown export, JSON import, and clear all

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Make local data portable and give users a safe, explicit erase workflow.

## Scope

- Reveal the real data directory using platform APIs and native file dialogs.
- Define a versioned JSON format covering snippets/tags/relationships/copy metadata; preserve full text and timestamps. Keep machine-specific paths, window bounds, and native app identifiers out of portable backups.
- Export JSON round-trip data and readable Markdown with robust code fences. Use atomic file writes and useful cancellation/error states.
- Validate imports before writes, bound file size, reject unsupported versions/malformed records, preview counts/conflicts, and import transactionally. Preserve deliberate duplicate texts; remap conflicting IDs and coalesce tag names without losing associations.
- Use typed confirmation for Clear all; erase library data/indexes/undo snapshots while retaining preferences/onboarding (explicit proposed v1 behavior). Coordinate with capture to prevent repopulation during erase.

## Acceptance criteria

- [ ] Export/import into a fresh profile restores full snippets, tags, timestamps, and copy metadata.
- [ ] Malformed/canceled/failed imports leave existing data unchanged and never execute imported text.
- [ ] Clear all requires the exact confirmation and updates every window/tray with no recoverable in-app undo.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
