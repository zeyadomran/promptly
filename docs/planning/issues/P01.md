# P01: Bootstrap Electron, React, TypeScript, and the modular project structure

Establish a runnable desktop foundation with strict boundaries and small, reusable modules.

## Scope

- Use Electron + React + TypeScript + Vite, Tailwind, npm with a committed lockfile, and Electron Forge for packaging; verify compatible stable versions during implementation.
- Create feature folders and enforce renderer/main import boundaries. Every React component, including extracted shadcn subcomponents, gets its own implementation file; preserve accessible primitive composition and provide explicit re-export entrypoints.
- Aim for 50–150 lines per handwritten module; flag files over 200 lines for extraction or a justified review exception. Keep orchestration thin and business logic outside JSX.
- Add lint, format, typecheck, test, dev, and package scripts; build a minimal Vitest/React Testing Library harness.

## Acceptance criteria

- [ ] A clean clone installs reproducibly and launches a React window on macOS and Windows.
- [ ] Renderer code cannot import Node, Electron main, database, or native adapters.
- [ ] Component-per-file and module-boundary checks run locally; no starter demo remains.

## Verification

Clean install, typecheck/lint, launch smoke on both platforms, and one meaningful preload-boundary smoke test.

## Boundaries and dependencies

- Phase 1: Foundation and risk validation.
- Depends on: None.
- Suggested module boundaries: src/main/, src/preload/, src/renderer/, src/shared/, forge.config.ts, package.json.
- One React component per implementation file; shared hooks/services own reusable behavior. Target 50–150 lines, review/extract files over 200 lines.
- Source coverage: SPEC §§1,9; user stack and modularity requirements.
