# [P24] Implement Windows system tray, recent snippets, and pause capture

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Keep Promptly available in the background with useful native tray commands.

## Scope

- Generate Windows tray assets from the supplied SVG, including a paused state.
- Build Open Promptly, five most recently updated snippets, Pause/Resume capture, Settings, and Quit menu items; truncate labels but copy full stored text.
- Route recent-item copy through the shared successful-copy service and refresh menu data after mutations/import/clear.
- Disable only save capture while paused; keep open/pin shortcuts functional. Respect tray visibility preferences and maintain an alternative reopen path.
- Dispose tray, shortcut hooks, helpers, timers, and database resources on explicit Quit.

## Acceptance criteria

- [ ] Recent items reflect capture/recapture/edit/delete and always copy full text.
- [ ] Paused state is visible and capture does not fire; resuming reinstates the selected shortcut.
- [ ] Quit exits fully, while normal hide/close preserves intended background behavior.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.

## Implementation checkpoint

The main-owned tray coordinator uses the existing Settings and Shortcuts services and the shared CopyService. Its five recent entries use the repository's updated-time ordering and resolve stored text again when clicked. Main-owned copy lifetimes carry no renderer identity and never hide a window; accepted clipboard writes and statistics drain before storage shutdown. Committed snippet changes refresh the menu, and a retired native-menu generation cannot dispatch commands or populate a replacement tray with a stale response.

Packaging derives light/dark, normal/paused multi-resolution Windows ICO assets from the supplied SVG. Actual taskbar rendering, OS clipboard fidelity, Explorer recovery, accessibility and Quit process termination remain manual Windows qualification; functional tests and package construction do not establish these outcomes.
