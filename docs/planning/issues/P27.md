# [P27] Audit design fidelity, keyboard accessibility, and assistive technology

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Verify the complete interface against the supplied designs and accessible behavior.

## Scope

- Compare the supplied visual references adapted to Windows: three-step onboarding, compact light/dark, regular light/dark, wide/narrow settings; also cover new Settings subsections using the same tokens.
- Check 4.5:1 text contrast, visible focus, icon labels/tooltips, dialogs, tag dots with text alternatives, OS key labels, reduced motion, and high DPI.
- Verify virtualized list roles/active-descendant behavior, selection independent of copy, focus return, screen-reader announcements, and complete keyboard flows.
- Test NVDA on Windows; record intentional Windows chrome and accessibility-driven differences from reference pixels.

## Acceptance criteria

- [ ] All applicable Windows screens have reviewed comparison artifacts and unresolved differences are filed.
- [ ] No critical keyboard traps, inaccessible icon controls, or unlabeled overlays remain.
- [ ] Settings remains usable around 640 px and with enlarged text; light/dark highlights retain contrast.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA and distribution requirements are manual Windows release checks where relevant. Performance measurements and budgets are skipped for this pass. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
