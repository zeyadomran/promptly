# P06: Build the shadcn design foundation, themes, and shared components

Turn the provided visual system into reusable components used by every screen.

## Scope

- Initialize real shadcn primitives using the Radix base for the specified Sonner behavior; match New York/zinc styling with semantic tokens rather than accepting unrelated preset visuals.
- Bundle Space Grotesk 400/500/600 and Geist Mono 400/500 locally with license files; no Google Fonts runtime calls. Use lucide-react and supplied logos/tray source assets.
- Define light/dark/system tokens, eight tag hues in the specified order, search highlights, spacing, typography, radii, focus rings, and reduced-motion rules.
- Add only needed primitives and split each React implementation into its own file, retaining normal composition through re-exports. Build Logo, ShortcutKey, TagDot, PinStatus, HighlightedText, and SettingsField as separate reusable components.
- Use local fixtures to inspect component states; avoid adding an unnecessary full component workbench dependency.

## Acceptance criteria

- [ ] Light/dark/system switching has no color transition flash and follows OS theme changes.
- [ ] Fonts and assets render offline; shared components match supplied reference measurements.
- [ ] Icon-only actions have labels/tooltips and overlays have accessible titles.

## Verification

Extend the canonical public functional service flow where necessary; run strict checks and Windows packaging. UI/native release qualification is manual.
