# [P07] Implement global shortcuts and the double-tap modifier state machine

> Current scope (2026-10-02): Windows x64 only. macOS is deferred and is not a dependency or release gate. #55 removes its implementation. Use minimal functional service tests, one canonical test per flow; native/UI qualification remains manual. This supersedes older cross-platform acceptance text and historical comments.

Trigger capture reliably while another application is focused.

## Scope

- Use Electron globalShortcut for combinations and the validated native hook for modifier taps. Support Shift, Ctrl, and Alt.
- Define a tap as press/release; trigger on the second completed tap within the configured window. Cancel on intervening keys, other modifiers, holds/repeats, pause, sleep, or hook reset.
- Register capture, show/hide, and optional pin combinations with Windows display labels; detect duplicates within Promptly and actual registration failures.
- Replace bindings transactionally, retaining previous valid bindings on failure. Suspend relevant capture during recorder use without leaving it disabled afterward.
- Handle resume/restart and unregister hooks/accelerators on quit. Pausing capture must not disable show/hide or pin.

## Acceptance criteria

- [ ] Normal typing and Shift-modified shortcuts do not cause false captures.
- [ ] 300 ms default and 150/600 ms boundaries behave deterministically.
- [ ] Failed/conflicting registration has honest status; no claim to identify every owning app.

## Verification

Extend the existing canonical public functional service flow only where needed; keep real internal services/storage and fake external OS/time boundaries. Run strict types, ESLint, Prettier, functional tests and Windows packaging. UI, native delivery, NVDA, installation and performance requirements are manual Windows release checks where relevant. No automated GUI/E2E suite, duplicate flow tests, stress gates or new test infrastructure.
