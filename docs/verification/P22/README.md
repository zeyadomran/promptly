# P22 storage transfer verification

The Storage tab uses the actual desktop bridge, owner-authorized IPC, SQLite worker and durable library services. Reveal calls `shell.showItemInFolder` for the configured database; native open/save dialogs belong to the originating window. Renderers cannot submit arbitrary filesystem paths or SQL.

## Portable format and import

JSON is UTF-8 with `format: "promptly-library"`, `version: 1`, snippets, tag definitions and memberships. It preserves snippet IDs, exact text, timestamps, copy count and last-copy timestamp. Window geometry, preferences, machine paths and source application identities are excluded. Conflicting snippet/tag IDs are remapped; existing matching tag metadata wins. In-file and existing-name coalescence use SQLite's actual `NOCASE` collation, including embedded NUL; associations are unioned and deliberate duplicate texts remain separate. See [SQLite's collation contract](https://www.sqlite.org/datatype3.html#collation).

The worker validates a regular file's actual bytes while reading, rejects invalid UTF-8, unknown fields/versions, invalid dates, duplicate/dangling IDs or associations and unsupported lone-surrogate tag names before any library write. Limits are 64 MiB, 20,000 snippets, 4,000 tags, 200,000 memberships, 100 memberships per snippet and 16 million total text code units. Existing individual text/name limits still apply. Oversize exports fail explicitly and never truncate. Valid surrogate pairs and NUL are preserved; new SQLite UTF-16 blobs preserve snippet lone surrogates losslessly. Markdown uses a fence longer than any embedded backtick run; normally UTF-8, it uses a BOM-marked UTF-16LE fallback when original lone surrogates require it.

Preview content is immutable and owned in the worker. Tokens belong to the original renderer, expire after five minutes, and are discarded on cancel, crash, navigation, window close, clear or quit. Confirmation rejects stale revisions and runs one transaction with rollback and one committed revision/change event. File edits after preview cannot alter the confirmed content. Native chooser cancellation does not mutate the library. Failed/expired preview dismissal returns keyboard focus to Import JSON.

Export serializes off the main thread, writes an exclusive temporary file beside the chosen destination, flushes and closes it, then renames atomically. Failure/cancellation removes the temporary file and leaves a previous destination intact. The active database and WAL/SHM paths are protected, including canonical directory aliases.

## Clear and shutdown

The bridge requires literal `CLEAR ALL`; the accessible dialog disables confirmation until the exact case-sensitive phrase is entered. Clear removes snippets, tags, memberships and undo snapshots; preferences/onboarding remain. The shared `LibraryMutations` owner invalidates queued writes and pre-clear capture tickets synchronously, drains already-running work before erasing, rejects saves during erase and accepts fresh captures afterward. Future capture must obtain `beginCapture()` before native selection and use `commitCapture(ticket, action)`. The capture pipeline and tray are pending issues; no physical capture/tray qualification is claimed here.

Transfer/capture acceptance stops and accepted library work settles before final window geometry, settings, SQLite and native shutdown. Main's existing shared normal/fatal 40-second coordinator remains authoritative. Closed/crashed renderer dialog results cannot later export or retain a preview.
